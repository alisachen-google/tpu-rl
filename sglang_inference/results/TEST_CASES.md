# Test-case catalogue: sglang-torchtpu 1-prefill + 1-decode on TPU v7x

What was run, how to run it again, what passed and what failed. Companion to `FINDINGS.md` (chronological log), `bug_reports/` (issue
drafts, `PRIORITIES.md`) and `COVERAGE.md` (plan review). All paths are relative to `sglang_inference/` in this repository unless noted.

Build under test: sglang-torchtpu `main` @ `09d1244c2641c3232ec0fcf5dd2d3bd372d5d709` (2026-10-07), sglang 0.5.13.dev7249; torch-tpu
0.1.1+release.2026.9.22, libtpu 0.0.47, torch 2.11.0+cpu, transformers 5.8.1. Two TPU v7x hosts (4 chips, 8 TensorCores, 944 GiB RAM each):
host a runs the prefill engine and the Python mini load balancer (port 8080), host b runs the decode engine. TP 8, EP 8 on each engine.
Models: `openai/gpt-oss-120b` (MXFP4, fp8 KV, page 64, sliding window 128) and `Qwen/Qwen3-VL-30B-A3B-Instruct` (bf16, fp8 KV, page 128).

## 1. Configurations

Recipes are `recipes/<model>_<cfg>_<shape>.json`, generated by `scripts/make_recipes.py` and loaded by the repo launcher
(`python -m benchmark.tpu.launch_server --config @recipe.json`). Shape `128k` = context 140,288, KV pool 786,432 tokens, 8 request slots;
`1m` = context 1,056,768, pool 1,114,112, 1 slot. Suffixes `_mr1/_mr2/_mr4` override the slot count, `_noswamem` adds
`--disable-hybrid-swa-memory`.

| Cfg | Prefill | Decode | gpt-oss | Qwen3-VL |
|---|---|---|---|---|
| A | radix cache off, raiden transfer | raiden receiver | done (128k, 1m, 256k/512k partial) | done (128k) |
| B | A + radix cache on | – | done (128k) | done (128k) |
| C | B + HiCache, `--hicache-io-backend raiden --hicache-mem-layout page_first_fused --hicache-ratio 2 --hicache-write-policy write_through` | – | done (128k) | done (128k) |
| D | C + EAGLE3 (`lmsys/EAGLE3-gpt-oss-120b-bf16`, bf16 KV, 3 steps, topk 1, 4 draft tokens) | EAGLE3, `cpu_tensor` retraction backup | done (128k) | n/a |
| E | D | + decode radix cache + decode HiCache (`SGLANG_UNIFIED_RADIX_TREE_CORE_BACKEND=python`) | done (128k) | n/a |
| G | monolithic golden, same flags, no disaggregation (fp8 and bf16 KV) | – | done | done |

Every PD run goes through the mini-LB; goldens are queried directly. Common runtime env (all recipes): `SGLANG_RAIDEN_TIMEOUT_S=600`,
`SGLANG_DISAGGREGATION_BOOTSTRAP_TIMEOUT=7200`, `SGLANG_DISAGGREGATION_WAITING_TIMEOUT=7200`, `SGLANG_RAIDEN_HOST_POOL_GB=128` (320 for 1m),
`SGLANG_TPU_FUSED_MOE_SC_GATHER=0` (gpt-oss), `TORCH_LOGS=+recompiles`.

## 2. How to run anything

```bash
S=~/pd_disagg/scripts; R=~/pd_disagg/results
bash $S/tpu_free.sh                                   # exit 0 only when no other user holds /dev/vfio on either host
bash $S/pd.sh start  recipes/gpt-oss_B_128k.json B_gpt-oss_128k     # pair: decode on b, prefill + LB on a; waits for health
bash $S/pd.sh golden recipes/gpt-oss_G_128k_fp8_e4m3.json G_x b     # monolithic server on host a|b
bash $S/pd.sh stop                                    # ours only
bash $S/_phase_config.sh gpt-oss B $R/golden/gpt-oss_fp8_rep2_c1    # the whole battery below for one config (TC-0,1,2,3,3b,4,6,7,8,9,10,11,12)
```
Recipes and scripts must exist on host a too (`rsync` them; `pd.sh` does not copy them). Logs: `results/runs/<RUN>/<role>/server.log`
(prefill log lives on host a; compressed copies of every run in `results/logs/runs/<RUN>/`). Prompt sets: `prompts/<model>/<isl>.jsonl`
(token-exact, 2 prompts per length, 3 needles each; `tiny.jsonl` = 35 exact lengths 1…16385), built with `scripts/build_prompts.py` and
`scripts/tiny_prompts.py`.

### Design and process notes learned in this period

- `--max-queued-requests` counts the newcomer itself: limit 0 refuses every request even into an idle server; with priority scheduling it crashes instead (fixed by refusing the combination at start-up or by an empty-queue guard).
- The mini-LB waits for both halves of a PD request and relays the prefill's status, so a decode-side refusal is only visible to the client if the prefill twin is also finished.
- A decode receiver can notify the prefill ranks only after `init()` resolved `bootstrap_infos`; a pre-dispatch ABORT needs that step first and a prefill that honours an ABORT arriving before its sender exists.
- The repo's TPU CI runs on demand per commit: post `/tag-and-rerun-ci` after each push, after the new head's workflow run exists; TPU jobs frequently time out on slice admission ("NOT ADMITTED after 3281s") and need `rerun-failed-jobs` once the run completes.
- Plugin boundary: fixes go through platform methods, registries or runtime patches under `sglang_tpu/`; the debt ratchet (`tools/plugin/check_tpu_branches.py`) fails lint for any new `is_tpu` branch or plugin import in core.
