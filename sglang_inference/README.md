## Plan corrections (verified in this build)
1. Transfer backend is `raiden`; attention backend `pallas_tpu_rpa_v3` (the `batched` kernel has no attention-sink support → gpt-oss would fail).
2. Host-RAM KV offload = HiCache with `--hicache-io-backend raiden --hicache-mem-layout page_first_fused`. No Raiden env var toggle.
3. gpt-oss: fp8 KV, page 64, `SGLANG_TPU_FUSED_MOE_SC_GATHER=0`; KV pool must be ≥ ~605k tokens (#363 precompile hang) and ≤ ~1.5M (OOM); chunk ≤ 8k. EAGLE3 draft `lmsys/EAGLE3-gpt-oss-120b-bf16` is on NFS (TC-4 unblocked for gpt-oss; spec recipes use bf16 KV).
4. Qwen3-VL-30B-A3B: no TPU recipe/test exists in the repo; the MoE decoder has no torch.compile policy (only the vision tower) → expect eager decode. To confirm on hardware; this is a TC-5 finding candidate.
5. Raiden transfer deadline `SGLANG_RAIDEN_TIMEOUT_S` (default 120 s) must match on both engines; set 600 in recipes. Measured VPC bandwidth 102–128 Gbit/s.
6. `SGLANG_ENABLE_UNIFIED_RADIX_TREE` is a deprecated no-op in this build.
7. Default LB is the Python mini-LB started by the launcher (what CI uses). The Rust router (`sglang-router` 0.3.2 wheel) is available as a variant: run `launch_router` with the repo bindings path removed from PYTHONPATH.
8. Already covered by wyzhang's prior campaigns (NFS `exp/1003-pd-fault-inj`, `1006-pd-stress`, `1005-recompile-patch-v2`): Raiden fault injection, 2P2D load swings, recompile audits at ≤131k. Focus here: 256k–1M, SWA chunk/window boundaries, multimodal MRoPE handoff, HiCache backpressure, all-features soak.
